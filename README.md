# 中国网球公开赛赛事运营管理系统

> 管理信息系统课程设计 · 系统分析与设计报告的 Python + MySQL 实现  
> 技术栈：Python 3 + Flask（B/S 三层架构）+ MySQL 8.0 + Bootstrap 5（本地内置，离线可用）

本系统按报告 4.2 节的五个模块实现：

| 模块         | 功能                                 | 角色          |
| ---------- | ---------------------------------- | ----------- |
| 模块1 系统管理   | 登录/退出、修改密码（全部内部角色）；账号与角色维护、操作日志（仅管理员） | 全部内部人员 / 系统管理员 |
| 模块2 基础数据管理 | 运动员档案（检索/增删改）、裁判档案与排班状态、场地档案与维护状态  | 系统管理员、赛事编排员 |
| 模块3 赛程编排管理 | 比赛录入、选手/场地/裁判三类冲突自动校验、赛程表筛选、CSV 导出 | 系统管理员、赛事编排员 |
| 模块4 成绩管理   | 比分录入（事务一致性）、胜负场次自动更新、统计报表与导出       | 系统管理员、成绩录入员 |
| 模块5 公开查询   | 免登录查询赛程、比分、选手资料（只读）                | 观众          |

- Python 3.10 及以上（本机验证环境：Python 3.13）

## 三、启动步骤

## 五、数据库设计（与报告 4.5 节对应）

| 报告表名         | 实际表名             | 说明                                               |
| ------------ | ---------------- | ------------------------------------------------ |
| PLAYER       | `player`         | 运动员档案、排名、外卡标识，另加 `win_count/loss_count` 支撑 FR-11 |
| REFEREE      | `referee`        | 裁判档案与排班状态（A 可排 / B 已排 / C 停用）                    |

| MATCH_PLAYER | `match_player`   | 参赛关联表，复合主键（match_id, player_id），team_no 区分双方     |
| STAFF        | `staff`          | 工作人员账号、角色、加盐哈希密码、失败次数与锁定时间                       |

## 六、核心业务规则的实现位置

| 规则                     | 实现位置                                                    | 说明                                      |
| ---------------------- | ------------------------------------------------------- | --------------------------------------- |
| BR-01 选手时间冲突           | `app/validation.py: check_conflicts()`                  | 同一选手时间区间重叠即拒绝，提示冲突比赛编号                  |
| BR-02 场地时段冲突 / 维护场地不排期 | 同上                                                      | 同一场地时间重叠或场地 `status='M'` 时拒绝，并给出可用场地清单  |
| BR-03 裁判执裁冲突 / 停用裁判    | 同上                                                      | 同一裁判时间重叠或 `duty_status='C'` 时拒绝，给出可替换裁判 |
| BR-04 成绩录入后锁定          | `validation.can_enter_score()` + `results.save_score()` | 只有"进行中"可录分，录入后置"已结束"，重复录入被拒             |
| 时间区间边界                 | `validation.intervals_overlap()`                        | 前一场结束时间 == 后一场开始时间**不算**冲突（TC-04）       |

成绩录入的三步一致性由 `db.transaction()` 保证：写比分 → 置状态 → 累加双方胜负场次，任一步失败整体回滚。

权限控制三级：角色决定菜单（`auth.MENU`）→ 蓝图决定可访问页面（`BLUEPRINT_ROLES` + `before_request`）→ 写操作视图再校验 `@auth.require_roles(...)`，直接输入网址无法绕过。

## 九、常见问题

| 现象                                               | 原因与处理                                                                        |
| ------------------------------------------------ | ---------------------------------------------------------------------------- |
| 页面提示"数据库连接失败"                                    | 1) MySQL 服务没启动；2) `.env` 的 `DB_PASSWORD` 不对；3) 没执行 `python tools/init_db.py` |
| `ModuleNotFoundError: No module named 'pymysql'` | 执行 `pip install -r requirements.txt`（装到当前 Python 环境）                         |
| `Access denied for user 'root'@'localhost'`      | `.env` 里的密码与本机 MySQL 不一致；或用户名不是 root（改 `DB_USER`）                            |
| `Table 'china_open.player' doesn't exist`        | 没建表：执行 `python tools/init_db.py`                                             |
| 端口被占用（macOS 的 5000 常被隔空播放接收器占用） | 默认已使用 5050，且程序会自动顺延到下一个空闲端口并在终端打印实际地址；也可 `python app.py --port 5060` 指定 |
| 登录后菜单比同学少                                        | 角色不同（管理员/编排员/录入员菜单不同），这是权限设计的正常表现                                            |
| 忘记管理员密码                                          | 重新执行 `python tools/init_db.py`（会重建演示账号，密码回到 123456，注意会重置数据）                  |

## 十、答辩时可讲的三个技术点

1. **冲突校验的时间区间判定**：把 `HH:MM + 预计时长` 换算成分钟区间，用 `a.start < b.end and b.start < a.end` 判断重叠，天然满足"首尾相接不算冲突"的边界要求；
2. **成绩录入的事务一致性**：`with db.transaction() as cur:` 把"写比分 / 置状态 / 累加胜负"三步绑成一个原子操作，异常整体回滚，避免报告 4.3 节说的"比分写了而胜负没更新"；
3. **三级权限控制**：菜单级（角色过滤）、页面级（蓝图权限守卫 + 403 页）、操作级（视图装饰器），并配合加盐哈希、登录锁定、会话超时与操作日志，落实报告 4.7 节。

## 附：重置本机 MySQL 的 root 密码（可选，macOS · Oracle MySQL 8.0）

如果你希望继续使用本机 3306 上的 MySQL（而不是项目自带的本地实例），可以按下面步骤重置 root 密码。
需要输入你的 **Mac 管理员密码**（sudo），并按你自己的 MySQL 安装路径调整（默认 `/usr/local/mysql`）。

```bash
# 1) 停止 MySQL 服务
sudo /usr/local/mysql/support-files/mysql.server stop

# 2) 以"跳过权限校验"的方式启动（不要关闭这个终端窗口）
sudo /usr/local/mysql/bin/mysqld_safe --skip-grant-tables --skip-networking &

# 3) 另开一个终端，无密码登录并重设 root 密码
/usr/local/mysql/bin/mysql -u root
#    进入 mysql> 提示符后依次执行：
#    FLUSH PRIVILEGES;
#    ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewPass123';
#    exit;

# 4) 关闭刚才那个跳过校验的实例
sudo /usr/local/mysql/bin/mysqladmin -u root -pNewPass123 shutdown

# 5) 正常启动 MySQL
sudo /usr/local/mysql/support-files/mysql.server start
```

改好之后，把 `.env` 里 `DB_PORT` 改成 `3306`、`DB_PASSWORD` 改成 `NewPass123`，
再执行 `python tools/init_db.py` 即可。

> 如果提示 `mysqld_safe: command not found`，说明你的 MySQL 不是 Oracle 官方安装包，
> 可以改用 `brew services stop mysql` / `brew services start mysql` 控制服务（路径相应换成 `$(brew --prefix)/bin/...`），
> 或者直接用项目自带的本地实例（推荐，最省事）。
