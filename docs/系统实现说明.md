# 系统实现说明（与设计报告对照）

> 本文说明《中国网球公开赛赛事运营管理系统分析与设计报告（精简版）》的设计内容在代码中的落地位置，

## 一、技术架构（对应报告 4.1 节）

报告设计的 B/S 三层架构在本系统中落为：

| 层次 | 报告设计 | 代码实现 |
| --- | --- | --- |
| 表示层 | 浏览器页面，表单录入、列表展示、报表呈现 | `app/templates/`（Jinja2）+ 本地 Bootstrap 5.3，`base.html` 统一版式（内部端左侧角色菜单 / 观众端公开版式） |
| 业务逻辑层 | Flask 路由 + 业务处理函数，权限判断、冲突校验、事务控制、统计 | `app/modules/*.py`（五个模块）+ `app/auth.py`（权限）+ `app/validation.py`（校验）+ `app/services.py`（公共查询） |
| 数据层 | SQLite 单文件数据库 | **MySQL 8.0**（按课程要求改用 MySQL，表结构与报告 4.5 节一致），`app/db.py` 负责连接与事务 |

请求处理链路：`浏览器 → before_request 会话/角色守卫 → 蓝图视图 → validation 校验 → db 访问 MySQL → Jinja2 渲染`。

## 四、关键实现片段（答辩讲解用）

### 1. 冲突校验的时间区间判定（报告 4.3 节表 7）

```python
# app/validation.py
def intervals_overlap(start_a, dur_a, start_b, dur_b):
    a1 = services.to_minutes(start_a); a2 = a1 + int(dur_a or 0)
    b1 = services.to_minutes(start_b); b2 = b1 + int(dur_b or 0)
    return a1 < b2 and b1 < a2      # 首尾相接（a2 == b1）不算重叠
```

编排保存时按"选手 → 场地 → 裁判"的顺序依次校验，冲突以列表返回：

```python
conflicts = validation.check_conflicts(
    match_date, start_time, duration_min, court_id, referee_id, players)
if conflicts:
    # 不写库，把每条冲突 + 候选空闲场地/裁判回显到表单下方
```

### 2. 成绩录入的事务一致性（报告 4.3 节末段）

```python
# app/modules/results.py（节选）
with db.transaction() as cur:
    cur.execute('UPDATE `match` SET set_score=%s, game_score=%s, actual_min=%s, '
                'status=%s WHERE match_id=%s', (...))
    for pid in winner_ids:      # 胜方全部选手（双打 2 人）胜场 +1
        cur.execute('UPDATE player SET win_count = win_count + 1 WHERE player_id=%s', (pid,))
    for pid in loser_ids:
        cur.execute('UPDATE player SET loss_count = loss_count + 1 WHERE player_id=%s', (pid,))
# 任一步异常：整个 with 块回滚，不会出现"比分写了胜负没更新"
```

### 3. 三级权限控制（报告 4.7 节）

| 级别 | 实现 | 生效点 |
| --- | --- | --- |
| 菜单级 | `auth.MENU` 中每项声明 `roles`，`visible_menu(role)` 过滤 | 侧边栏只显示本角色功能 |
| 页面级 | `auth.BLUEPRINT_ROLES` + `app/__init__.py` 的 `before_request` | 直接输网址也返回 403 页（TC-08） |
| 操作级 | 写操作视图 `@auth.require_roles('admin', 'scheduler')` 等 | 越权 POST 同样被拦 |

配套安全措施：密码 `werkzeug.security` 加盐哈希（pbkdf2）；连续 3 次密码错误锁定 10 分钟（`staff.fail_count / locked_until`）；
会话 30 分钟无操作超时；删除与状态变更写 `sys_log` 操作日志。

## 八、安全与健壮性加固（独立验收后补充）

独立验收审查（见 `tests/qa_report.md`）发现的问题已全部修复并回归验证，答辩时可以作为"安全性设计"的补充说明：

| 加固点 | 实现方式 | 位置 |
| --- | --- | --- |
| 登录跳转防开放重定向 / 头注入 | `safe_next_url()` 只允许本站相对路径，拒绝 `http(s)://`、`//`、`javascript:`、CRLF 与控制字符 | `app/auth.py` |
| 会话实时校验（降权/停用立即失效） | 每次请求从 `staff` 表读取当前角色与状态，与会话不一致就清会话并重新登录 | `app/__init__.py` `guard()` |
| 轻量 CSRF 防护 | 所有 POST 校验 `Origin`/`Referer` 与本站同源，跨站来源直接 403；Cookie 设置 `SameSite=Lax`、`HttpOnly` | `app/__init__.py`、`config.py` |
| 调试模式默认关闭 | `APP_DEBUG` 默认 `0`，异常页只显示友好提示，细节写日志 | `config.py` |
| CSV 公式注入防护 | 导出时对以 `= + - @` 开头的单元格加前导单引号 | `app/services.py` `csv_safe()` |
| 成绩锁定与历史保护 | 已结束比赛不允许改状态、不允许删除、不允许重复录分（BR-04） | `schedule.py`、`results.py`、`validation.py` |
| 用户枚举防护 | 登录失败提示统一为"账号或密码错误。" | `app/auth.py` |
| 数据库异常友好提示 | 写库异常只记录日志，页面提示中文原因，不暴露 SQL | `schedule.py` |

> 说明：未引入完整 CSRF token 机制（课程设计规模下的取舍），其余上述加固均已通过独立复现脚本回归验证。
